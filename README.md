# 🌱 OpenSource-FirstStep

**Your first step into Git, GitHub, CI/CD, and Open Source!**

Welcome to **OpenSource-FirstStep**, a beginner-friendly, hands-on learning repository designed to help you understand how real-world developers collaborate, manage code, automate checks, and contribute to open-source projects.

You don't need to be an expert to start. Learn one concept, practice it, and share what you learn with others.

## 🎯 What You'll Learn

- 📚 **Git Fundamentals** — repositories, commits, staging, and version control.
- 🌿 **Branches and Merging** — create branches, merge changes, and resolve conflicts.
- 🤝 **GitHub Collaboration** — forks, issues, pull requests, and code reviews.
- ⚙️ **CI/CD with GitHub Actions** — automate tests and detect errors before merging code.
- 🐛 **Debugging** — understand failed checks and fix common Git mistakes.
- 🌍 **Open-Source Contributions** — find beginner-friendly issues and contribute to real projects.
- 📝 **Contribution Guidelines** — learn how to make your own project welcoming to others.

## 🛠️ Prerequisites

Before starting, you'll need:

- A [GitHub account](https://github.com/)
- [Git](https://git-scm.com/downloads) installed on your computer
- A code editor such as [Visual Studio Code](https://code.visualstudio.com/)
- Basic terminal knowledge (you can learn it along the way)

Python will be useful when we build our automated testing examples.

## 🚀 Getting Started

### Step 1: Clone the repository

```bash
git clone https://github.com/SakshiBisht-2005/OpenSource-FirstStep.git
cd OpenSource-FirstStep
```

### Step 2: Create a feature branch

```bash
git switch -c feature/my-first-lesson
```

### Step 3: Make a change

Create or edit a lesson file and add something useful.

### Step 4: Commit your change

```bash
git add .
git commit -m "Add my first lesson"
```

### Step 5: Push your branch

```bash
git push -u origin feature/my-first-lesson
```

### Step 6: Open a pull request

Visit your repository on GitHub, open a pull request from your feature branch into `main`, review your changes, and merge when everything looks good.

**Congratulations!** You've practiced the basic collaboration workflow used by developers around the world.

- Testing instructions and reporting errors.

Please read [CONTRIBUTING.md](CONTRIBUTING.md) before submitting a pull request.
